# PC-Mem Midterm Demo

A standalone local demo of PC-Mem's personal-file knowledge graph: a document
tree, real version chains, project ownership, an extracted concept graph, and
cited answers. It is **not** an agent framework and it does **not** modify the
`personal-agent` repository; it calls the same `sci_rag` ingest, graph, retrieval
and answer paths that the project's evaluation scripts use.

The Chinese edition is [readme_ZH.md](readme_ZH.md).

```
pcmem-demo/
├── readme.md                 ← this file
├── readme_ZH.md              ← Chinese edition
├── run.sh                    ← launch the live demo
├── pcmem_demo/               ← Python backend (stdlib HTTP + sci_rag calls)
├── web/                      ← live browser UI (HTML/CSS/JS, no framework)
├── sample_corpus/            ← fixed 14-document, 7-format demo corpus
├── tests/                    ← 14 offline tests (no DB, no model)
├── tools/                    ← ontology sync + portable-bundle packager
├── recordings/               ← live-demo screen recording, no audio
├── pcmem-static-demo/        ← fully static, pre-recorded version (no backend)
├── pcmem-static-demo.zip     ← shippable copy of the static site
├── .state/                   ← runtime only: key, demo PostgreSQL, build report (do not ship)
└── dist/                     ← generated portable bundle (do not ship)
```

## What each folder does

| Path | What it does |
| --- | --- |
| `run.sh` | Starts the demo-local PostgreSQL cluster (port 5544), then the stdlib HTTP server on `127.0.0.1:8770`, using `../personal-agent/.venv`. |
| `pcmem_demo/` | The backend. `paths.py` points at the sibling repo; `secrets.py` stores the API key at mode 0600; `config.py` builds `sci_rag.Settings`; `pipeline.py` runs ingest → version replay → project ownership → mentions → graph extraction → optional communities → answers; `views.py` projects the DB; `server.py` serves the API/SSE; `runtime.py` owns one asyncio loop; `jobs.py` tracks builds. |
| `web/` | The live UI: document tree, Canvas force-directed graph, node/edge cards, timeline, community summaries, ask panel, retrieval trace, build modal, settings. |
| `sample_corpus/` | A fixed synthetic corpus with 14 current documents, 7 formats, 4 top-level folders and one 3-revision version chain. `manifest.json` carries metadata; `project_rules.yaml` holds ordered glob ownership rules; `_history/` holds revisions replayed through the real ingest path. |
| `tests/` | Offline checks for the corpus, ontology, project rules, secret store, static assets and light theme. Run with `../personal-agent/.venv/bin/python -m unittest discover -s tests -v`. |
| `tools/` | `make_ontology.py` regenerates `pcmem_demo/ontology.json` from `../personal-agent/domain-personal/domain.yaml`; `package_bundle.sh` assembles a portable bundle from this demo plus a clean commit of the sibling repo. |
| `recordings/` | `pcmem-demo-live.mp4` (34 s, 1440×900, H.264, no audio) and a poster frame. It records the live page with real model calls: node/edge cards and the preset budget question. |
| `pcmem-static-demo/` | A self-contained static fork of the same UI with a fixed snapshot and a scripted playback. Its banner says “static / no model / no API key”; the live controls are disabled. Open it with any static file server, or `file://`. It has its own README. |
| `pcmem-static-demo.zip` | Packaged static site for handing to someone who only needs to view it. No backend, no key, no model. |
| `.state/` | Created at runtime. Holds `secrets.json` (0600 API key), `pgdata/` (demo PostgreSQL on 5544) and `build_report.json`. **Never ship this directory.** |
| `dist/` | Generated by `tools/package_bundle.sh`: a portable `pcmem-demo-bundle/` + `.tar.gz` containing the demo and a slim `personal-agent` source tree. Gitignored. |
| `../personal-agent/` | Sibling dependency, not inside this folder. Provides `src/sci_rag`, `domain-personal`, `scripts/local_postgres.py`, `pyproject.toml`, `uv.lock` and the venv. |
| `readme.md`, `readme_ZH.md` | This folder map and the live/static distinction, in English and Chinese. |

## Live demo vs static demo

| | Live (`run.sh` → 8770) | Static (`pcmem-static-demo/` → 8780) |
| --- | --- | --- |
| Backend | Python + PostgreSQL + `sci_rag` | none |
| Model | real OpenAI-compatible endpoint | none |
| API key | required for build/ask | **not required** |
| Data | built from `sample_corpus/` | one fixed snapshot in `snapshot.js` |
| Ask | real retrieval and streamed answer | one preset playback triggered by “▶ 播放预录演示” |
| Claim | live demo | clearly labelled static, pre-recorded |

## Quick start (live)

Requirements: `uv`, Python 3.11–3.12, PostgreSQL 16–18 + pgvector, and an
OpenAI-compatible model endpoint.

```bash
./run.sh
# http://127.0.0.1:8770/
```

On first open, use **模型设置** to save the base URL, key, answer model and
extraction model. Then **重建图谱**; the build takes about 2–3 minutes.
Community summaries are optional and slower.

The demo creates its own PostgreSQL cluster under `.state/pgdata` on port 5544
and never touches the repository's `.env` or its default database. Stop the
demo database with:

```bash
../personal-agent/.venv/bin/python -m pcmem_demo.cli pg-stop
```

## Static preview

```bash
cd pcmem-static-demo
python3 -m http.server 8780 --bind 127.0.0.1
# http://127.0.0.1:8780/
```

The page makes no `/api/*` calls, no model calls, and contains no key. The
header explicitly says **static pre-recorded snapshot**. The playback button
is new to the static version and is not present in the live UI.

## Security

- The API key is stored only in `.state/secrets.json` with mode 0600. It is
  never returned to the browser, never written to logs, and never put in a URL.
- The server binds `127.0.0.1` by default; it refuses a non-loopback host unless
  `--allow-remote` is explicit. It has CSP, no CORS, and an Origin check.
- `pcmem-static-demo/` contains no secret and no backend.
- Do not ship `.state/` (key + local 66 MB database) or `../personal-agent/.venv/`
  (machine/architecture-specific).

## Portable bundle

```bash
./tools/package_bundle.sh
# dist/pcmem-demo-bundle/
# dist/pcmem-demo-bundle.tar.gz
```

It copies this demo (excluding `.state`, `dist`, `recordings`, caches) and a slim
source tree from a committed `personal-agent` revision (`git archive HEAD`).
The recipient still needs `uv`, PostgreSQL + pgvector, and a model key. See the
generated `SETUP.md` in the bundle.

## Recording

`recordings/pcmem-demo-live.mp4` is a page-level Chromium recording of the live
demo, encoded with ffmpeg: 34 s, 1440×900, H.264, **no audio**. macOS Screen
Recording permission was not available to the agent, so the recording covers
the page content (no desktop or browser chrome), not a desktop-window capture.
It uses the live backend and real model; the static version is the separate
`pcmem-static-demo/` folder.

## Tests

```bash
../personal-agent/.venv/bin/python -m unittest discover -s tests -v
```

14 offline tests pass. They do not need PostgreSQL or a model.

## Notes and limits

- The sample corpus is synthetic and is not a benchmark.
- The vector layer is the repository's offline `local-hash` (1024 dimensions),
  not Qwen3; the UI labels it honestly.
- The demo enables the LLM reranker for answer quality and leaves HyDE off by
  default (the switch is in the UI). These are demo choices, not benchmark
  defaults.
- Community summaries are optional and are skipped in the answer path whenever
  a retrieval scope is present, matching the repository's design.
- The demo needs PostgreSQL. It is not a static-only deployment; the static
  folder is the zero-dependency viewer.
